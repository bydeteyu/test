# 키워드 리서치 보드

바이럴 마케팅 키워드 리서치를 클라이언트별로 관리하는 팀 워크플로우 보드입니다. 클라이언트 인테이크(업종·목표·타겟·우선 채널·금지어)와 키워드 리서치·평가·채택 여부를 한 곳에서 관리합니다.

## 로컬 실행

```
npm install
npm start
```

`http://localhost:3000` 에서 확인할 수 있습니다.

## 구조

- `server.js` — Express 서버. `/api/projects`, `/api/keywords` REST API와 정적 파일(`public/`)을 제공합니다.
- `public/index.html` — 프로젝트 탭, 인테이크 카드, 키워드 리서치 테이블로 구성된 단일 페이지 UI.
- 데이터는 `DATA_DIR`(기본값 `./data`) 아래 `db.json` 파일에 저장됩니다. 서버 재시작 후에도 파일이 남아 있으면 데이터가 유지되지만, 배포 환경에 영구 볼륨이 연결되어 있지 않으면 재배포 시 초기화될 수 있습니다.

## 평가 기준

키워드 평가 점수는 검색량/버즈량 30%, 경쟁강도 20%(낮을수록 유리), 트렌드지속성 20%, 브랜드적합성 20%, 확산가능성 10%의 가중 합산으로 계산되며, 70점 이상이면 자동으로 "채택"으로 표시됩니다.

## 배포

Railway 등 Node.js를 지원하는 플랫폼에 배포할 수 있습니다. `npm start`로 서버가 실행되고, `PORT` 환경 변수를 사용합니다. 데이터를 재배포 후에도 유지하려면 `DATA_DIR`이 가리키는 경로에 영구 볼륨을 연결하세요.

## 카페 모니터링

프로젝트 상세 화면의 "카페 모니터링" 카드에서 카페명과 감시 키워드(쉼표 구분)를 저장한 뒤 "지금 검색 실행"을 누르면, [네이버 검색 오픈 API](https://developers.naver.com/docs/serviceapi/search/cafearticle/cafearticle.md)로 해당 키워드가 제목/본문 요약에 포함된 카페글을 검색하고, 결과 중 지정한 카페명과 일치하는 글만 걸러 보여줍니다.

- **범위**: 네이버 검색에 공개적으로 색인된 글의 제목/설명만 매칭합니다. 가입·등급이 필요한 비공개 카페의 게시글 본문은 확인하지 않으며, 검색에 잡히지 않을 수 있습니다.
- **댓글은 자동으로 작성하지 않습니다.** 발견된 글의 링크를 열어 담당자(한의사)가 직접 댓글을 작성하는 용도입니다.
- 사용하려면 [네이버 개발자센터](https://developers.naver.com/apps/#/register?api=search)에서 애플리케이션을 등록하고 "검색" API를 추가해 발급받은 Client ID/Secret을 환경 변수로 설정하세요.

```
NAVER_CLIENT_ID=...
NAVER_CLIENT_SECRET=...
```

Railway에서는 프로젝트 설정의 Variables 탭에 위 두 값을 추가하면 됩니다. 값이 없으면 "지금 검색 실행"이 오류 메시지를 표시하고 아무 것도 하지 않습니다.

## AI 키워드 확장

"AI 키워드 확장" 카드의 "발견된 글 분석해서 키워드 제안받기"를 누르면, 카페 모니터링으로 찾은 글의 제목·설명을 Claude API에 보내 사람들이 추가로 검색해볼 법한 키워드 후보를 제안받습니다.

- AI는 발견된 글에 실제로 등장하거나 암시된 표현만 근거로 삼도록 지시되어 있고, 이미 감시 중인 키워드와는 중복 제안하지 않습니다.
- 제안은 곧바로 반영되지 않고 "채택 / 무시" 검토를 거칩니다. 채택하면 해당 키워드가 감시 키워드 목록과 키워드 리서치 표에 자동으로 추가되어, 다음 카페 검색부터 함께 감시됩니다 — 이렇게 검색 → 분석 → 키워드 확장 → 재검색이 반복되며 키워드 풀이 계속 넓어집니다.
- 사용하려면 [Anthropic Console](https://console.anthropic.com/)에서 발급받은 API 키를 환경 변수로 설정하세요.

```
ANTHROPIC_API_KEY=...
CLAUDE_MODEL=claude-haiku-4-5-20251001   # 선택, 기본값
```

## 글 수동 등록 (가입이 필요한 카페용)

가입·등급이 필요한 비공개 카페는 검색 API에 잡히지 않고, 본문 복사도 막혀 있는 경우가 많습니다. "카페 모니터링" 카드 하단의 "글 수동 등록" 폼으로 해결합니다.

- **스크린샷 업로드**: 담당자가 폰/PC에서 캡처한 이미지를 올리면 Claude Vision이 이미지에 실제로 보이는 내용만으로 제목·내용 요약을 추출해 등록합니다. 복사가 막혀 있어도 캡처는 항상 가능합니다.
- **직접 입력**: 이미지 없이 제목(+선택적으로 링크)만 입력해도 등록됩니다.
- 이렇게 등록된 글도 "AI 키워드 확장" 분석 대상에 그대로 포함됩니다. 목록에는 자동검색/수동/스크린샷 출처가 표시됩니다.
- **스크린샷은 업로드 즉시 키워드도 제안합니다.** 이미지를 분석하는 같은 요청에서 그 글 내용을 근거로 한 바이럴 키워드 후보를 뽑아 "AI 키워드 확장" 대기 목록에 바로 추가하므로, 별도로 "발견된 글 분석해서 키워드 제안받기"를 누르지 않아도 됩니다.

## 순위 체크 (웹 페이지 `/rank.html`)

기존 카페 모니터링(노출 알림)과 **별개**로 동작하는 순위 체크 페이지입니다. 프로젝트를 고르고 "검색 키워드"와 추적할 콘텐츠(제목에 포함된 문구 또는 글 주소)를 등록한 뒤 "지금 확인"을 누르면, 통합검색은 노출 여부만, 카페 탭은 50위까지 순위를 확인해 최근 7일 표로 보여줍니다.

- 서버가 매일 오전 9시(KST) 이후 처음 확인 시점에 전체 항목을 자동 실행합니다. 끄려면 `RANK_AUTO=off`. 관련 환경 변수: `RANK_AUTO_HOUR`(기본 9), `RANK_MAX`(기본 50), `RANK_SNAPSHOT_MAX`(기본 50), `RANK_DELAY_MS`(기본 3000).
- 데이터는 `DATA_DIR/rank.json`에 따로 저장되어 기존 `db.json`과 카페 모니터링에는 영향이 없습니다. 같은 키워드를 쓰는 항목은 한 번만 조회합니다.
- 네이버가 서버 IP의 요청을 막으면(HTTP 403 등) 해당 칸이 `-`로 기록됩니다. 그 경우 아래 CLI를 PC에서 실행하는 방식을 쓰세요.

## 네이버 순위 체커 CLI (`rank-tracker/`)

키워드별로 지정한 콘텐츠(블로그/카페 글)가 **① 통합검색 ② 카페 탭**에서 노출되는지와 순위(예: `통합 5위 / 카페 16위`, 기본 50위까지 확인, `maxRank`로 변경)를 확인해 날짜별로 누적하고 순위표(`report.html`)를 만듭니다. 웹 앱과 별개로 실행되는 CLI입니다.

```
cp rank-tracker/config.example.json rank-tracker/config.json   # 키워드/대상 편집
npm run rank        # 결과: rank-tracker/data/history.csv, report.html
npm test            # 파서 단위 테스트
```

- 대상은 `match`(글 URL 일부, 예: `cafe.naver.com/카페명/글번호`) 또는 `titleContains`(제목 포함 문구)로 지정합니다.
- 순위 = 검색 결과 페이지에서 게시글 링크가 나타나는 순서(중복 제거). 통합검색은 블로그·카페 등 모든 게시글 기준, 카페 탭은 카페 글 기준입니다. 조회 실패는 "미노출"과 구분해 `-`로 기록합니다.
- **1일 1회 실행**: cron(`0 9 * * * cd /경로 && npm run rank`) 또는 GitHub Actions `schedule`로 돌리세요. 같은 날 재실행하면 그날 기록을 덮어씁니다.
- 공식 API가 아니라 검색 결과 HTML을 읽습니다. 네이버 화면 구조 변경·요청 차단 시 결과가 0건이 될 수 있고(경고 출력), 개인화/지역/기기에 따라 실제 화면과 순위가 다를 수 있습니다. 요청 간격(`delayMs`)을 두고 소량만 조회하세요. 이용약관은 직접 확인하시기 바랍니다.

## 웹 배포 (Railway / Render / Docker)

`npm start`가 `PORT` 환경 변수로 `0.0.0.0`에 바인딩하므로 Node.js를 지원하는 호스팅에 그대로 올릴 수 있습니다. 헬스체크 경로는 `/healthz` 입니다.

- **필수: `APP_PASSWORD`** — 설정하면 모든 페이지/API에 로그인(HTTP Basic, 아이디 기본값 `admin`, `APP_USER`로 변경)이 필요합니다. 공개 URL로 배포할 때는 반드시 설정하세요.
- **Railway**: GitHub 저장소 연결 → Variables에 `APP_PASSWORD`, `NAVER_CLIENT_ID`, `NAVER_CLIENT_SECRET`(필요 시 `ANTHROPIC_API_KEY`) 추가 → Volume을 `/data`에 마운트하고 `DATA_DIR=/data` 설정 → 발급된 도메인의 `/rank.html` 접속.
- **Render**: `render.yaml`(디스크 포함)을 사용하는 Blueprint로 배포. 디스크는 유료 플랜이 필요합니다.
- **Docker**: `docker build -t board . && docker run -p 3000:3000 -v board-data:/data -e APP_PASSWORD=비밀번호 board`
- 영구 볼륨이 없으면 재배포 시 데이터가 초기화됩니다. 또한 클라우드 서버 IP는 네이버가 막을 수 있어 순위가 `-`로 나올 수 있습니다.
